# Соответствие моделей и физических тел

6 ноября 2026. Исследованы исходники JS-проекта, реальные GLB Bunny / Sumo,
физические формы Planck и деформированные вершины в Chrome. Unity не запускалась.

## Причина двух дефектов на скриншотах

Общий источник — две независимые системы описания персонажа. Физика использовала
одинаковые примитивы для разных моделей, а рендер менял скелет поверх физической позы.
Это не единичное неверное смещение корневого объекта: ошибка зависит от части тела,
направления, позы, состояния захвата и выбранной модели.

### Физическая форма не была получена из меша

`BunnyRig` создавал капсулу корпуса 0.36 × 0.56 м, голову радиусом 0.155 м,
две капсулы стоп 0.16 × 0.11 м и два круга кистей радиусом 0.06 м.
Sumo получал те же формы; менялось только наличие сенсоров ушей.
У плеч, предплечий, бёдер и голеней собственных форм столкновения не было.

В исходной позе Bunny с направлением вправо измеренная нижняя граница кожи
корпуса находилась примерно на −0.165 м относительно Core. Низ старой капсулы —
−0.280 м: разница около **11.5 см**. При повороте меняется опорная часть, поэтому
это не универсальная величина зазора, но она непосредственно показывает скрытую
опору вне модели. У головы диапазон кожи по Y был примерно +0.325…+0.515 м,
тогда как круг задавался центром +0.340 м и радиусом 0.155 м.
Начало кости головы не является центром её видимого объёма.

### Поза модели расходилась с физической позой

- `footGather` сводил две видимые стопы в общую промежуточную точку, хотя два
  физических тела оставались раздельными. Поворот стоп также задавался визуальным
  поворотом таза, а не соответствующим физическим телом.
- Свободная кисть строилась от плечевой кости модели. К физической кисти она
  подводилась отдельным сглаживаемым коэффициентом. Плечевая кость и origin
  физической руки при этом не совпадали.
- Смещение живота, разворот таза на 25°, пружины запястий и масштабирование
  перчатки изменяли меш без изменения физических форм.
- Дополнительные анимации удара выносили стопу до 30 см, кисть до 38 см относительно
  физической позы. Это могло вновь нарушить соответствие даже после исправления захвата.
- Предыдущая коррекция захвата проверяла край перчатки против **коллайдера** цели.
  Касание с неверным коллайдером не доказывает касание с видимой моделью цели.

### Обнаруженные сопутствующие ошибки

1. У Bunny кость `Tail` и меш хвоста имеют одно исходное имя в `userData`.
   Обход с безусловной записью в Map мог заменить ссылку на кость ссылкой на меш.
2. `updateWorldMatrix()` сам по себе не обновляет `SkinnedMesh.bindMatrixInverse`.
   CPU-измерение поверхности до полного `updateMatrixWorld()` могло использовать
   устаревшую матрицу скиннинга, отличающуюся от последующего GPU-рендера.
3. Стандартный радиус оболочки полигонов Planck — 1 см. У прямоугольных поверхностей
   окружения он тоже добавлял опору за пределами нарисованного пола.
4. После добавления форм конечностей контакт голени нельзя считать контактом стопы:
   иначе мотор стойки пытается удерживать персонажа в неподходящей позе.

## Исправление

### Данные модели вместо общего набора примитивов

`tools/export-assets/colliders.mjs` читает поставляемые GLB через Three.js без
браузера и текстур. Экспортируются и skinned meshes, и жёсткие дочерние меши:
лица, детали Sumo и хвост Bunny. Результат — `src/config/characterGeometry.json`.

Сохраняются исходные преобразования узлов, привязки вершин к костям и смешанные
веса на сгибах. Для жёстких участков сохраняется достаточный набор экстремальных
вершин; для сгибающихся участков сохраняются смешанные вершины и пространственная
выпуклая оболочка жёстких вершин. У частей Core, которые всегда движутся вместе,
смешанные веса сворачиваются без изменения их положения.

Контуры строятся по текущей коже отдельно для корпуса, головы и каждой части
конечностей, ушей и хвоста. Они разбиваются на полигоны с не более чем 12 вершинами.
При разбиении учитывается порог сварки вершин Planck, чтобы тонкая остаточная часть
никогда не превращалась в запасной квадрат 2 × 2 м. Отдельный тест проверяет этот случай.

Хеш GLB проверяется тестом. Отпечаток экспортированной геометрии включён в формат
совместимости повторов: записи со старой физикой отклоняются.

### Общая поза скелета

`CharacterSkeleton` используется физикой, рендером и Node-повторами.
Каждая стопа следует своему физическому телу. Каждая кисть следует своему
физическому телу во всех состояниях. Смещение между origin кости и центром видимой
перчатки / стопы измеряется из модели. IK начинает каждый расчёт с исходных длин;
при необходимости длина корректируется одинаково для кожи и формы столкновения.

Рендер копирует рассчитанные преобразования костей. Независимые смещения,
изменявшие контактную геометрию только на экране, удалены. Вспышки попаданий,
шкалы здоровья и числа урона сохранены. При совпадении имён выбирается кость.
После установки позы полностью обновляются матрицы skinned meshes.

Физические формы кожи обновляются на фиксированных тактах, вне `World.step`;
рендер не изменяет физические тела. Обновление сохраняет идентичность fixture,
когда число частей контура не меняется. Массы 9.2 кг на персонажа и калиброванные
инерционные параметры сохранены; это параметры движения, а не дополнительные
скрытые коллайдеры.

### Захват реальной поверхности

Поиск использует контур перчатки, а не предположение о круге фиксированного размера.
Шарнир закрепляет ближайшие точки двух поверхностей с допуском 5 мм.
Столкновения с удерживаемым телом остаются включёнными.

Учитывается и Z: положение контактной части перчатки по глубине согласуется с
контуром кожи цели. Эта глубина входит в общий расчёт скелета, поэтому изменение
также учитывается формой руки. Самостоятельного смещения нарисованной кисти нет.

Для малого остаточного расхождения шарниров после solve добавлены два ограниченных
прохода позиционного ограничения. Они перемещают **физические тела** пропорционально
обратным массам, не меняют скорости и не исправляют большие ошибки телепортацией.
После этого формы кожи пересчитываются. Это устраняет остаточный зазор захвата при
одновременной работе плечевого шарнира и контактов конечностей.

Контакт стопы определяется по области `Foot`, а не по всему телу ноги.
При перекате ноги подбираются, а моторы рук ослабляются, чтобы стойка не боролась
с вращением полного физического силуэта. Момент переката на опоре увеличен с 30
до 50 Н·м: при прежнем значении увеличенное плечо реальной геометрии могло оставлять
персонажа в устойчивой лежачей позе. Перекат до выхода за край и завершения матча
проверен в настоящем браузерном сценарии. Число позиционных итераций — 6, шаг — 0.02 с.

Отладочные контуры используют ту же интерполированную позу, что и модель.
У полигонов персонажа и окружения отключена лишняя сантиметровая оболочка.

## Проверки

Проверки измеряют деформированную геометрию настоящих GLB, а не только начала костей.
В тестах контуры сравниваются также с вершинами реальных полигонов Planck.

| Проверка | Объём | Измеренный результат |
| --- | --- | --- |
| Контуры моделей против реальных физических форм | 330 областей / поз, Bunny и Sumo, оба направления, пять углов, разные положения конечностей | максимальное расхождение опорных контуров 2.304 мм |
| Захват видимого соперника | 138 состояний кистей: голова, корпус, стопа; оба направления; Bunny / Sumo; первый такт и удержание; alpha 0 / 0.5 / 1 | максимальное расстояние от поверхности перчатки до треугольников модели 4.631 мм |
| Падение на пол | 8 сценариев: обе модели, четыре исходных ориентации | минимальная вершина кожи по Y от −5.050 до −3.513 мм; положительного зазора над полом нет |
| Длительная игра | 10000 тактов, по 5000 на Flat и Meadow, четыре игрока | конечные координаты, ограниченное число тел, корректная очистка |
| Массы и инерции | пять динамических тел | сохранены; ошибка относительно измеренных значений менее 4.8 × 10⁻⁸ кг и 1.1 × 10⁻⁹ кг·м² |

Небольшая отрицательная высота контакта с полом соответствует допуску проникновения
решателя. Проверяется отсутствие скрытой опоры выше поверхности, а не искусственное
приподнимание меша для маскировки проникновения.

- `npm run build`: TypeScript и production-сборка проходят.
- `npm test`: **35/35**.
- `npm run test:browser`: **9/9** на dev-сервере, без ошибок загрузки в UI-сценариях.
- Production-проверка через `BUNNY_TEST_URL=http://127.0.0.1:4173`: **3/3** UI-сценария;
  шесть проб с импортом исходных модулей намеренно пропущены, они прошли на dev-сервере.
- `git diff --check`: проходит.
- `npm run compare:unity`: обновлён отчёт траекторий; это измерение изменений,
  а не проверка тождественности решателей.

Сырые данные: [measurements.json](collider-alignment/measurements.json),
[исходные границы кожи](collider-alignment/before.json),
[браузерный прогон](collider-alignment/browser-tests.json),

Текущее сравнение с прежним Unity-эталоном приведено в `unity-comparison.json`:
ошибка пика одиночного прыжка теперь около **22.72 мм**. Старое значение 0.35 мм

геометрия и момент переката изменены сознательно.

Сборка сообщает о крупном общем JS-чанке: примерно 2.04 МБ, 593 КБ gzip,
включая экспортированные данные кожи. Это предупреждение размера, сборка завершена успешно.

## Границы точности

Игра использует Planck в плоскости XY и объёмный рендер Three.js. Здесь обеспечивается
соответствие физических областей проекции текущей кожи и отдельно проверяется 3D-касание
при захвате. Перехода на объёмный 3D-решатель не было. Области выпуклые: локальные
вогнутости внутри одной области заполняются. Нулевая погрешность до каждого треугольника
во всех возможных состояниях не заявляется; допуски геометрии, контактов и ограничения
решателя проверяются явно. Сравнение с прежней капсульной физикой Unity больше не
является критерием правильности формы тела.

## Повторная генерация

Из корня проекта:

```sh
node tools/export-assets/colliders.mjs
npm run build
npm test
npm run test:browser
```

После изменения GLB данные нужно пересоздать. Одного подбора чисел в `bunnyTuning.ts`
для изменения формы персонажа больше не требуется.

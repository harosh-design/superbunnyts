# Super Bunny JS

Браузерный перенос Super Bunny: локальный Deathmatch на 2–4 игроков,
обе исходные боевые карты и одиночная Physics Lab. TypeScript + Planck + Three.js.
Unity для запуска готовой игры не нужен.

## Запуск

Нужны Node.js 22.12+, браузер с WebGL 2 и клавиатура.

```sh
npm ci
npm run dev
```

Открыть адрес Vite, обычно http://localhost:5173/. В меню выбрать арену,
2–4 игроков, число жизней и модель P1 (Bunny или Sumo). Enter, Space или прыжок
P1/P2 начинают матч; T открывает одиночную лабораторию. Музыка и эффекты
разблокируются действием пользователя. `?mute=1` запускает без звука.

## Управление

| Игрок | Прыжок | Перекат | Захват (удерживать) |
| --- | --- | --- | --- |
| P1 | W | A / D | Space |
| P2 | ↑ | ← / → | Right Shift |
| P3 | U | H / K | V |
| P4 | Num 8 | Num 4 / Num 6 | Num 0 |

R — начать сцену / матч заново, Esc — пауза / продолжение, Q — главное меню,
M — включить / выключить звук. Клавиши определяются по физическому коду,
поэтому работают при русской раскладке. Разворот по S исключён по решению
пользователя; направление задаётся при появлении персонажа.

Одно нажатие прыжка даёт один толчок вдоль локального верха корпуса.
Удержание не повторяет прыжок, нажатие в воздухе не сохраняется до приземления.
Две руки хватают независимо, только при касании поверхности кистью
(допуск решателя 5 мм). Край кисти закрепляется непосредственно на поверхности;
физическое закрепление уточняется после solve, а поза кисти и её коллайдер
получаются из одного скелета. Глубина кисти согласуется с поверхностью модели соперника. При отпускании сохраняются скорости.
Потеря фокуса или скрытие вкладки ставит игру на паузу; продолжение вручную.

## Режимы и правила

- **Deathmatch · Flat:** исходная платформа, две пружины, четыре точки появления.
- **Deathmatch · Meadow:** острова, верхние уступы, центральная платформа,
  шипы в яме и на стенах, семизвенная лиана, две наклонные пружины.
- По умолчанию 10 жизней. Отсчёт 3 с блокирует действия игроков.
- На каждую жизнь даётся 100 HP. Полоска здоровья видна над каждым
  игроком, оставшиеся жизни — в панели счёта. HP не восстанавливаются до следующего возрождения.
- Урон наносит удар живого соперника по голове: кистью, стопой или другой
  частью тела. Учитываются скорость сближения в точке удара (включая вращение)
  и фактический нормальный импульс столкновения. Касания до 2 м/с безопасны.
  Урон = `0.5 × импульс × max(0, скорость − 2) × 2`, максимум 100 HP.
  За 0.25 с от одного соперника засчитывается один удар; несколько коллайдеров
  и обе стопы не умножают урон одного удара. Отталкивание от чужой головы тоже
  наносит урон, пропорциональный импульсу стопы, без мгновенного убийства.
- Попадание сопровождается всплывающей цифрой фактического урона, вспышкой
  и физическим движением атакующего. Дополнительный визуальный вынос
кисти / стопы за пределы её коллайдера исключён. Эффекты замирают на паузе.
- При 0 HP отнимается одна жизнь, нанёсший последний удар получает KO.
  Удары головой об обычные поверхности и предметы HP не снимают.
  Шипы и выход за границы по-прежнему отнимают жизнь сразу.
- После смерти тело остаётся на 0.65 с, затем плавно погружается
  в землю за 1.8 с. Столкновения и чужие захваты отключаются сразу.
  Возрождение через 2.7 с, после завершения погружения, в самой дальней
  от живых соперников точке. При последней жизни новая модель не появляется.
- Последний игрок с жизнями побеждает. Реванш доступен кнопкой или прыжком
  любого игрока через 1.5 с после результата.
- **Physics Lab:** один игрок без боевых смертей, исходная груша массой 4 кг
  на четырёх динамических звеньях. R восстанавливает всю лабораторию.
- Дополнительные одиночные сцены: пол, выступ, стена, динамический предмет,
  лиана, вертикальная пружина и пружина 30°. Выбор — в меню лаборатории или
  раскрывающейся панели «Инструменты».

## Модели, обстановка и физика

Bunny и Sumo экспортированы из исходных `.blend` в `public/assets/models/`:
геометрия без упрощения, нормали, UV, материалы, скелет. Face / FaceDead и текстуры
лица переключаются при смерти. В лаборатории Bunny сохраняет исходный розовый
цвет; в матче костюм получает цвет игрока, как в Unity. Имена костей проверяются
при загрузке; при совпадении имени меша и кости приоритет имеет кость.
`CharacterSkeleton` задаёт общую позу для рендера и физики. Каждая стопа и кисть
следует своему физическому телу, с учётом положения реальной геометрии относительно кости.
Независимые визуальные смещения живота, стоп и кистей исключены.

Контуры корпуса, головы, конечностей, ушей и хвоста получены из GLB отдельно
для Bunny / Sumo. Смешанные веса кожи сохраняются; при сгибании физические формы
обновляются на фиксированных тактах. Коллайдеры — выпуклые области в плоскости XY,
разбитые на допустимые полигоны Planck, а не прежние универсальные капсулы.
Диагностика учитывает интерполяцию позы. Подробный разбор причин и проверки:
[reports/COLLIDER_ALIGNMENT.md](reports/COLLIDER_ALIGNMENT.md).

Статическая обстановка и геометрия обеих арен экспортированы из сохранённых
Unity-сцен; `src/config/arenas.json` содержит платформы, шипы, пружины,
точки появления и границы. Оригинальные WAV лежат в `public/assets/audio/`.

На персонажа приходится пять динамических тел, два ползунковых и два шарнирных
сустава, масса 9.2 кг. Шаг 0.02 с, гравитация −7.8 м/с², solver 50/6.
Инерция тел измерена в Unity и явно задаётся через адаптер Planck. У полигонов персонажа и окружения убрана лишняя оболочка Planck толщиной 1 см.

Физическая идентичность двух решателей не заявляется. После перехода на контуры моделей старые показатели совпадения траекторий
с капсульным эталоном Unity являются историческими. Текущие проверки и границы точности: [reports/VALIDATION.md](reports/VALIDATION.md).
Свет, материалы рендера и браузерный интерфейс также не являются попиксельной
копией Unity. Камера дополнительно расширяет обзор в матчах на 3–4 игроков,
чтобы крайние участники оставались видимы.

## Запись, повтор и диагностика

В панели «Инструменты» доступны физические формы, контакты, суставы,
центры масс, фиксированная камера и счётчик отброшенного времени.

«Записать» начинает свежую сцену и сохраняет ввод всех игроков по тактам.
Максимум — 15000 тактов (5 минут). Сброс, выход в меню и реванш завершают запись.
Повтор можно проиграть, скачать в JSON или загрузить. Версия физики и настройки
матча проверяются при загрузке. Воспроизведение в Node без DOM / WebGL:

```sh
npm run replay -- /path/to/recording.json
```

## Сборка и проверки

```sh
npm run build
npm run preview
npm test
npm run test:browser
npm run compare:unity
```

`build` проверяет TypeScript и создаёт `dist/`. Раздавать каталог через HTTP;
`file://` не поддерживается. Браузерные проверки выключают звук. На macOS
используется установленный Chrome; на других системах подготовить Chromium:
`npx playwright install chromium`. Для проверки production-сервера можно задать
`BUNNY_TEST_URL=http://127.0.0.1:4173 npm run test:browser`.

## GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` собирает игру и публикует `dist/`
при push в `main`, а также поддерживает ручной запуск через `workflow_dispatch`.

1. Отправить workflow в основную ветку репозитория.
2. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. Для ручной публикации открыть **Actions → Deploy to GitHub Pages → Run workflow**,
   выбрать `main` и нажать **Run workflow**.

Базовый путь сборки определяется настройками Pages автоматически. Ссылка на сайт
появится в environment `github-pages` после успешного выполнения workflow.

## Повторный экспорт исходников

```sh
"/Applications/Blender 2.app/Contents/MacOS/Blender" --background --factory-startup --python tools/export-assets/bunny.py -- --model bunny
"/Applications/Blender 2.app/Contents/MacOS/Blender" --background --factory-startup --python tools/export-assets/bunny.py -- --model sumo
node tools/export-assets/colliders.mjs
bash tools/unity-reference/capture.sh
```

Экспорт читает соседний `Super Bunny` и не сохраняет изменения в его файлы.
Unity работает в отдельной временной копии; логи остаются в ней. GLB сопровождаются
хешами исходника и результата. Эталон, его происхождение и хеши исходников находятся
в `reference/unity-runtime/current.json` и `current.source.json`.
После повторного экспорта GLB нужно заново выполнить `colliders.mjs`: тесты
проверяют соответствие хешей моделей. После нового захвата Unity нужно проверить
измерения перед обновлением `unityMass.ts`.
